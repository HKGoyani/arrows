Read this first — no iOS build of 1.0.8 has been verified

The ad changes in this release were developed and tested on Android (debug and release, on real devices). They are Dart-level, so they apply to iOS too, but none has run on an iPhone. This is also the first iOS release on Flutter 3.47.5 (1.0.7 shipped on 3.41.6). Treat the device test in Section 10 as mandatory.

The "no app-open ad after Control Center" claim in What's New is reasoned from how Flutter reports inactive on iOS, and reproduced only for the Android notification shade. Soften or drop that bullet if the iPhone test doesn't confirm it.

What's changed since v1.0.7 (build 11)

Version 1.0.7 → 1.0.8, build 11 → 12. Two code commits (ad behaviour, then the toolchain). Almost nothing a player can see; mostly ad-delivery tuning.

Player-visible

ChangeStatusDetail
App-open ad only after really leaving the app FIXED The resume ad treated Flutter's inactive state as backgrounding. On Android that fires for the notification shade, the Play billing sheet and the review card; on iOS the equivalent is Control Center, Notification Center and system prompts. An ad could be fetched there and shown on the way back. Now it needs a real hidden/paused first. iOS BY ANALOGY Reproduced on Android only

Ad pipeline (not player-visible)

ChangeStatusDetail
Win and lives-refill ads: one request per level attemptDONEBoth triggers fire on every board change; after a no-fill every tap re-requested. Verified on Android with forced no-fill. iOS fills at ~99.9%, so this rarely triggers there
Ad retries stop when the level attempt endsDONERetries used to fire on Home or in the next level
Restart ad requested only when it can showDONESkipped for restarts under 3 arrows (no confirm dialog) and inside the 45s inter-ad gap
Home banner kept instead of discardedDONEA banner that finished loading after a level covered Home is now held and shown on return (15 min, Remove Ads and consent guards). iOS Home banner show rate was 44%
Banner analytics on real impressionDONEad_shown for banners logs on impression, not on load

6. App Review Notes

REQUIRED Not shown to users — read only by Apple's reviewer. This is a different audience and purpose from What's New: what changed under the hood and how to verify it. Paste this into App Review Information → Notes on submission (1963 characters):

Arrows - Escape Puzzle is a single-player offline puzzle game. No login or account is required to play.

This build (1.0.7 -> 1.0.8) changes ad-delivery behaviour only. No gameplay rules, purchases, permissions, or data collection changed:
- The app-open ad (shown when the user returns to the app) now appears only after the app was actually sent to the background. Previously, briefly opening Control Center or Notification Center could also trigger it.
- Ad requests were reduced: the post-win and lives-refill ads are requested once per level attempt, retries stop when a level attempt ends, and the Restart ad is requested only when the Restart confirmation is actually shown.
- The Home banner, if it finishes loading just as the user starts a level, is now kept and shown on return to Home instead of being discarded.
- Firebase Analytics (anonymous, aggregated, no PII): the banner ad_shown event now logs on a real impression rather than on load, and one new event, ad_discarded (ad unit name + reason), was added to the existing usage events.
- Built with an updated Flutter SDK (3.47.5).

To observe the app-open change: leave the app with the Home gesture, wait a moment, and return - an ad may show (at most once every 3 minutes). Pulling down Control Center and dismissing it does not trigger one.

Unchanged from the previous submission:
- All gameplay progress is stored locally on-device (no server backend).
- One in-app purchase: "Remove Ads" ($3.99, non-consumable, product ID remove_ads) disables banner/interstitial/app-open ads. Rewarded ads (opt-in, for hints/extra lives) remain available even after purchase by design - disclosed in the purchase description shown in Settings.
- Ad mediation is Google AdMob with Unity Ads only.
- No account creation, no chat, no user-generated content, no web view with unrestricted browsing.

Test path: tap Play on the Home screen to start the current level, or Level 1 (tutorial) on a fresh install.
