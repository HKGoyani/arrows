What's changed since v1.0.1 (build 4, rejected under 4.3(a))

Build number bumped from 4 to 8, version name 1.0.1 → 1.0.4. This build carries several sessions of ad-monetization and stability fixes on top of v1.0.1 — none of them design/UI changes, since the open App Store issue (Section “Current Review Status” below) is unrelated to any of this.

ItemStatusDetail
Meta Audience Network mediation removed DONE gma_mediation_meta dropped entirely — it was never configured in AdMob console mediation groups, so it was inert weight. Mediation is now Unity Ads only. Privacy policy and SKAdNetwork entries updated to match (see Sections 6 & 9)
Daily challenge ad switched to plain interstitial DONE Previously a rewarded interstitial shown with no intro/skip screen — a departure from Google's documented format policy. Now shows the same plain interstitial a normal level win uses: fully compliant, no reward, no popup
Cold-start App Open ad fix DONE The splash's 5s budget was being consumed by consent/ATT/SDK-init before the ad fetch even started (SDK init alone measured up to 14.7s on Android), so the cold-start ad was frequently lost outright. Fixed the missing early-ready signal and added a grace window so a late-loading ad still shows right after Home appears
Banners switched to Large Anchored Adaptive format DONE Both Home and gameplay banners now request Google's taller Large format for better eCPM/fill potential. Layout already reserves space off the actual returned size, so no screenshot changes are expected — being monitored for fill-rate impact
Fixed a game-freezing bug DONE Backgrounding and foregrounding the app (min-max) while a rewarded/interstitial/app-open ad was on screen could let the OS reclaim that ad's native view without ever calling its dismiss delegate — freezing the game on that screen and silently blocking every ad after it for the session. Added a resume-time recovery path
App Store subtitle updated DONE Metadata-only change made alongside the 4.3(a) reply (2026-08-18) — see Section 1
Interstitial ad-loading is now demand-driven DONE (prior to v1.0.1, carried forward) Each ad format loads at the moment it becomes likely to be needed (e.g. win interstitial at ~80% board cleared, rewarded lives at 1 heart) instead of preloading everything at level start — unchanged this version, listed for completeness

Current Review Status — read before submitting

v1.0.1 (build 5) was rejected twice under Guideline 4.3(a) — Design: Spam (2026-08-08 follow-up, after an initial 2026-08-01 rejection). Apple's finding: the app shares a similar binary/metadata/concept with an existing title. A reply was sent on 2026-08-18 arguing the app is independently coded (no shared source/assets, not a template, single account/app) and pairing it with the subtitle change in Section 1 — no other design changes were made, per an explicit product decision to hold the current name/icon/visual identity rather than rebrand.

If this build is submitted and rejected under 4.3(a) a third time, escalate to a full rebrand (new name outside the current word pool, new icon, new visual identity) rather than appealing again — a repeated 4.3 rejection risks escalating from an app-level review to a developer-account-level review, which would expose every other Shayona title on this account.

12. App Review Notes

Paste this into the "Notes" field on submission:

Arrows – Escape Puzzle is a single-player offline puzzle game. No login
or account is required to play.

This build (1.0.1 → 1.0.4) contains ad-delivery and stability fixes
only — no design, UI, or content changes:
- Removed an unused ad mediation SDK (Meta Audience Network) that was
  never actually active; mediation is now Unity Ads only.
- Fixed a rare freeze that could occur when switching apps while a
  full-screen ad was on screen.
- Improved reliability of the ad shown on app launch.
- Simplified the ad shown after completing a Daily Challenge to match
  the same format used after a normal level win.

Unchanged from the previous submission:
- All gameplay progress is stored locally on-device (no server backend).
- One in-app purchase: "Remove Ads" ($3.99, non-consumable, product ID
  remove_ads) disables banner/interstitial/app-open ads. Rewarded ads
  (opt-in, for hints/extra lives) remain available even after purchase
  by design — disclosed in the purchase description shown in Settings.
- Firebase Analytics is used for anonymous, aggregated usage events only
  (no PII collected).
- No account creation, no chat, no user-generated content, no web view
  with unrestricted browsing.

Test path: tap Play on the Home screen to start Level 1 (tutorial),
or tap an in-progress level number to continue.
