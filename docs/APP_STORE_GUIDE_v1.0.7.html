Read this first — this build has never been compiled for iOS

Every change below was developed and verified on Android. As of this document, no iOS build of 1.0.7 has been produced, and nothing here has run on an iPhone. The App Store is still on 1.0.4 (build 8), which means iOS has missed three releases of ad-pipeline, performance, and gameplay-correctness work.

Two changes are Dart-level and therefore affect iOS identically once built — the self-firing arrow fix (which changes generated board layouts) and the performance work. Neither has been seen running on iOS hardware. Treat Section 13's device-test step as mandatory, not a formality.

What's changed since v1.0.4 (build 8)

Version 1.0.4 → 1.0.7, build 8 → 11. Seventeen commits spanning three Android releases (1.0.5, 1.0.6, 1.0.7). Grouped by whether a reviewer or player could notice.

Player-visible

ChangeStatusDetail
Arrows no longer fire through their own bodies FIXED An arrow flies by snaking along its own path plus a straight extension from the head, so a wound arrow whose own cells sat ahead of its head would visibly fly through its own tail. Affected 269 arrows across 140 of the first 250 levels, starting at level 38. Guards added at all three generation sites plus a repair pass on every board. This changes generated board layouts on affected levels — a few tail cells become empty. Verified: levels 1–250 and 120 daily boards, zero self-firing, zero unsolvable, zero empty
Banner removed from the gameplay screen DONE The gameplay banner took 73% of the account's ad requests for 5% of revenue at a 4.76% match rate. Removed entirely. The board area is now unobstructed during play — see Section 4, existing screenshots may show this banner
Levels load without freezing the UI FIXED Level generation ran on the UI isolate and was measured at 680–780ms for levels 70–93 on a fast machine — far worse on real devices. Now generated off-isolate, with restarts replayed from a cached pristine board (instant). This was the dominant cause of Android ANRs; on iOS the same work was simply a multi-hundred-millisecond freeze on every level start
Stopped rebuilding the whole screen every frame FIXED A tutorial-only finger animation was driving a full-screen rebuild and board repaint at 60fps on every level, not just the tutorial. Now runs only during the tutorial and stops when it ends
Sound effects pre-loaded; no audio-focus grab FIXED Every tap previously re-ran the full load/prepare/request-focus chain on the platform thread. Sounds are now pooled and pre-loaded, and the app no longer requests audio focus at all — tapping an arrow will no longer interrupt the player's music or podcast, which is the right behaviour for a casual puzzle game

Ad pipeline (not player-visible, but changes ad behaviour)

ChangeStatusDetail
Restart interstitial moved to the Restart tap DONE Was requested at two hearts remaining, on the assumption a restart was coming. Most players did not restart, so the ad was fetched and discarded — roughly 3,300 matched ads wasted per day. Now requested when Restart is actually offered
Home banner request churn cut DONE Returning to Home re-requested the banner immediately and retried aggressively. Now debounced by 1s with a still-on-this-route re-check, and retry caps trimmed. Worst case per Home visit: 12 requests → 4
Banner size standardised DONE CORRECTS v1.0.4 GUIDE The v1.0.4 guide stated banners use Google's Large Anchored Adaptive format. That was reverted on 2026-08-27: a week of data showed no eCPM premium ($0.25 either way) while the large format's thinner inventory cost fill speed. Both placements now use the standard anchored-adaptive size
Ad pipeline overhaul DONE Signal-driven loads, leak fixes, and a rewarded-skip path — shipped in 1.0.5, carried forward

Android-only changes — deliberately NOT in this build

Two fixes from 1.0.7 are Android manifest entries with no iOS equivalent. Listed so they are not mistaken for cross-platform work, and because one of them has an unaddressed iOS counterpart.

ChangeiOS status
Impeller lazy shader initialisation — ImpellerLazyShaderInitialization in AndroidManifest.xml, added because ANR traces showed the platform thread blocked in nativeSurfaceCreated while the raster thread compiled GLES shaders on slow PowerVR GPUs N/A — iOS Impeller uses Metal, not GLES, and does not have this eager-compile stall
Portrait lock — android:screenOrientation="portrait" on MainActivity, added because SystemChrome.setPreferredOrientations only constrains the Flutter view and has no reach over AdMob's ad activity, which was rendering landscape UNADDRESSED — ios/Runner/Info.plist still lists UIInterfaceOrientationLandscapeLeft and LandscapeRight under UISupportedInterfaceOrientations. That is the same gap the Android fix closed: full-screen ad view controllers can adopt an orientation the plist permits even though the Flutter view is locked. Not reproduced on iOS — flagged by analogy, not by observation. See Section 13

Current Review Status — the 4.3(a) issue is resolved

v1.0.4 is LIVE on the App Store. The Guideline 4.3(a) — Design: Spam rejection that blocked v1.0.1 twice was resolved by appeal, with no changes to the app. The product decision to hold the name, icon, and visual identity rather than rebrand was upheld.

The v1.0.4 guide's contingency advice — that a third 4.3(a) rejection should trigger a full rebrand rather than another appeal — is now moot for that thread, but worth keeping in mind as precedent if a future submission draws the same guideline. No rebrand was needed and none was done.

4. Screenshots

Action needed — the gameplay screen changed

Unlike v1.0.4, this version does change what the app looks like. The banner at the bottom of the gameplay screen is gone.

Check every uploaded screenshot. Any that shows a gameplay board with a banner strip beneath it now misrepresents the app and should be retaken. Screenshots of Home, Challenge, Collection, and Settings are unaffected — those still carry the banner.

Board layouts also shift slightly on levels 38 and above (self-firing fix). If any screenshot shows a specific high-numbered level, that exact board may no longer generate identically. Screenshots of levels below 38 are unaffected.

12. App Review Notes

Paste this into the "Notes" field on submission:

Arrows - Escape Puzzle is a single-player offline puzzle game. No login
or account is required to play.

This build (1.0.4 -> 1.0.7) brings iOS up to date with three Android
releases. Changes are performance, ad-delivery, and one gameplay
correctness fix:
- Fixed a bug where an arrow could animate through its own tail when
  fired. Board generation was corrected; no rules changed.
- Removed the banner ad from the gameplay screen.
- Level generation moved off the UI thread, so levels no longer pause
  before appearing.
- Sound effects are pre-loaded, and the app no longer requests audio
  focus, so playing no longer interrupts the user's own audio.
- The ad shown after tapping Restart is now requested at that moment
  rather than in advance.

Unchanged from the previous submission:
- All gameplay progress is stored locally on-device (no server backend).
- One in-app purchase: "Remove Ads" ($3.99, non-consumable, product ID
  remove_ads) disables banner/interstitial/app-open ads. Rewarded ads
  (opt-in, for hints/extra lives) remain available even after purchase
  by design - disclosed in the purchase description shown in Settings.
- Ad mediation is Google AdMob with Unity Ads only.
- Firebase Analytics is used for anonymous, aggregated usage events only
  (no PII collected).
- No account creation, no chat, no user-generated content, no web view
  with unrestricted browsing.

Test path: tap Play on the Home screen to start Level 1 (tutorial),
or tap an in-progress level number to continue.
