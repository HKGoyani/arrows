Read this first — verified on Android only

This release is a one-behaviour ad fix, written in Dart, so it applies to iOS identically. It was tested on an Android device (debug build, test ads); it has not run on an iPhone. Treat the short device test in Section 7 as mandatory.

iOS is the platform hurt most by the bug this fixes: the restart ad nearly vanished there (707 → 4 requests a week). Shipping 1.0.9 to iOS is what brings it back.

What's changed since v1.0.8 (build 12)

Version 1.0.8 → 1.0.9, build 12 → 13. One code commit (8c19f6f): the restart interstitial request, restored to its 1.0.7 behaviour. Nothing else changed.

Ad pipeline (not player-visible, but changes ad behaviour)

ChangeStatusDetail
Restart ad requested on every Restart tap RESTORED 1.0.8 stopped requesting it for early restarts (<3 arrows) and inside the 45s inter-ad gap, and removed the reload on the skip path, assuming those requests could never be shown. They could: an early restart loads an ad into the cache and the next restart shows it, and almost all restarts are early ones. The 1.0.8-only AdMob data showed restart requests falling 96–99% (iOS 707 → 4, Android 21,628 → 316) and about 5% of ad revenue going with them
What a player sees SAME AS 1.0.7 Restart interstitials show at the 1.0.7 rate again (at most one every 45 seconds, shared with win ads). Players on 1.0.8 saw almost none. No new ad type, placement or frequency
Everything else from 1.0.8 KEPT App-open only after a real background, once-per-attempt win/lives requests, retries tied to the level attempt, Home banner parking, banner analytics on impression, ad_discarded event, Flutter 3.47.5 toolchain

Evidence (internal — not for Apple)

1.0.8-only AdMob data, Oct 1–7, iOS: restart interstitial 4 requests, 3 impressions (1.0.7 week: 707 requests, 556 impressions, $1.19). Overall 1.0.8 is a clear win on iOS (show rate 61.8% → 80.7%, Home banner 44% → 91%), so this release keeps all of that and restores only the restart ad.

4. App Review Notes

REQUIRED Not shown to users — read only by Apple's reviewer. Different audience and purpose from What's New: what changed under the hood and how to verify it. Paste into App Review Information → Notes (1805 characters):

Arrows - Escape Puzzle is a single-player offline puzzle game. No login or account is required to play.

This build (1.0.8 -> 1.0.9) changes one ad-delivery behaviour only. No gameplay rules, purchases, permissions, SDKs or data collection changed:
- The interstitial ad that can appear after the Restart button is requested on every Restart tap again. Version 1.0.8 had stopped requesting it for early restarts (fewer than 3 arrows fired) and for restarts shortly after another interstitial, which unintentionally almost removed that ad. This restores the behaviour of version 1.0.7, which was previously approved.
- Ad frequency is unchanged: interstitials are limited to at most one every 45 seconds, and nothing is shown to users who purchased "Remove Ads" (rewarded ads remain opt-in only).

To observe it: start a level, tap the restart icon in the top bar (it restarts at once when fewer than 3 arrows have been fired), then restart again. An interstitial ad may appear on a later restart. Ads depend on ad availability, so one will not show every time.

Unchanged from the previous submission:
- All gameplay progress is stored locally on-device (no server backend).
- One in-app purchase: "Remove Ads" ($3.99, non-consumable, product ID remove_ads) disables banner/interstitial/app-open ads. Rewarded ads (opt-in, for hints/extra lives) remain available even after purchase by design - disclosed in the purchase description shown in Settings.
- Ad mediation is Google AdMob with Unity Ads only.
- Firebase Analytics is used for anonymous, aggregated usage events only (no PII collected).
- No account creation, no chat, no user-generated content, no web view with unrestricted browsing.

Test path: tap Play on the Home screen to start the current level, or Level 1 (tutorial) on a fresh install.
